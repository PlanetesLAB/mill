# Synthetic data and provenance

All numerical data in this folder are generated by the notebook. No observations
or published simulation outputs are included.

| File | Content |
| --- | --- |
| background.csv | Homogeneous Poisson realization: x_over_H, y_over_H |
| particles_with_clumps.csv | Background plus injected particles; x_over_H, y_over_H, origin |
| control_points.csv | Separate, independent homogeneous control field |
| control_cell_counts.csv | Counts in disjoint control-field cells |
| provenance.json | Seeds, generating parameters, units, package versions, and file hashes |

The origin column is 0 for the background, 1 for clump A, and 2 for clump B.
It identifies the generating component; it is not a physical membership
probability. A background-origin tracer can lie inside an overdense neighborhood.
Detection scores do not use this column.

The box is [0, 1) by [0, 1) in units of a chosen H. Periodic distances wrap across
opposite boundaries. They are a geometrical device, not a shearing-box
hydrodynamics solver. Each tracer has equal numerical weight. The chosen
intensity of 10,000 tracers per H squared is not an observed dust density.

The background and control totals are drawn from Poisson distributions, then
positions are uniform conditional on those totals. Each injected component has
a fixed number of positions drawn from a wrapped isotropic Gaussian.

Re-running all cells overwrites these same generated files. SHA-256 hashes in
provenance.json describe the actual exported CSV bytes. Figures and
verification.json live beside this data folder.
